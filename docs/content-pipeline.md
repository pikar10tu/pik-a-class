# โฟลวสร้างและตรวจเนื้อหา (Content pipeline)

> ทำตามลำดับนี้ทุกครั้งที่จะเพิ่มเนื้อหาเข้าคลัง — ออกแบบไว้ใน `docs/superpowers/specs/2026-09-20-data-layer-design.md` ข้อ 8
> แยก session ระหว่าง "เขียนโค้ดฟีเจอร์" กับ "generate เนื้อหา" ตามที่ `PLAN.md` §15 แนะนำ

**ข้อจำกัดที่ต้องรู้ก่อน:** เว็บเป็น static site ไม่มี backend — การเสิร์ช/ดึงข้อมูลจากอินเทอร์เน็ตเกิดตอน *แต่งเนื้อหา* ใน Claude Code session เท่านั้น ไม่ใช่ตอนนักเรียนใช้งาน (ถ้าให้เบราว์เซอร์ยิง search API คีย์จะรั่วและมีค่าใช้จ่ายต่อครั้ง)

## ชั้น 1 — ก่อน generate: เลือกเป้าหมายให้ชัด

1. เลือก **level + skill + tag** ที่จะทำรอบนี้จาก `src/lib/schema/taxonomy.js` (tag id เช่น `grammar:present-perfect`, `vocab:food-drink`)
2. ดูว่าคลังยังขาดอะไร — รันกับไฟล์เนื้อหาที่เคยทำไว้:
   ```
   npm run check:content -- docs/examples/exercises-sample.json
   ```
   ท้ายรายงานจะบอก "ยังไม่มีข้อเลย: ..." ต่อเลเวล ใช้เลือกหัวข้อรอบถัดไปได้เลย
3. กำหนดจำนวนข้อและชนิด (`mcq` / `fill_blank` / `matching` / `short_answer` / `paragraph` / `shadowing`) ก่อนเริ่ม

## ชั้น 2 — ตอน generate: ใช้ web search หาวัตถุดิบ

ค้นหาเพื่อให้โจทย์ **หลากหลายและเป็นภาษาที่คนใช้จริง** ไม่ใช่วนอยู่แต่ประโยคตัวอย่างเดิมๆ:

- คลังคำศัพท์ตามความถี่จริง (Oxford 3000/5000, CEFR wordlist) เพื่อเลือกคำให้ตรงเลเวล
- ประโยค/บริบทร่วมสมัยจากแหล่งจริง (ข่าว บทความ บทสนทนา) เพื่อเอาโครงสร้างประโยคและสถานการณ์มาใช้
- สถานการณ์ที่ผู้เรียนไทยเจอจริง (โรงเรียน ที่ทำงาน การเดินทาง)

> **กติกาลิขสิทธิ์ — ห้ามข้าม:** ห้ามคัดลอกข้อสอบหรือข้อความยาวจากเว็บมาตรงๆ ใช้เป็นวัตถุดิบแล้ว **แต่งใหม่เสมอ** และบันทึกที่มาไว้ทุกข้อในฟิลด์ `source` / `sourceUrl` เพื่อให้ตรวจย้อนได้ภายหลัง

**รูปแบบไฟล์:** JSON array ของข้อ ดูตัวอย่างที่ `docs/examples/exercises-sample.json`
ฟิลด์ที่ **ไม่ต้องใส่เอง** — ระบบเติมให้ตอนนำเข้า: `createdAt`, `updatedAt`, `createdBy`, `importBatchId`, `contentHash`, และค่าเริ่มต้นของ `reviewStatus` (`draft`), `isPreview` (`false`), `visibility` (`bank`), `assignedUids` (`[]`)

## ชั้น 3 — ตรวจอัตโนมัติ (ต้องผ่าน 0 ข้อผิดก่อนไปต่อ)

```
npm run check:content -- <ไฟล์ใหม่.json>
```

สคริปต์ตรวจให้ทั้งหมดนี้: ฟิลด์ครบและชนิดถูกตาม schema, MCQ มีคำตอบถูกข้อเดียวและเฉลยอยู่ในตัวเลือกจริง, ตัวเลือกไม่ซ้ำ, `fill_blank` มีช่องว่าง `___` พอดี 1 ช่อง, ข้อเขียนตอบมี `rubric`, tag มีอยู่จริงและไม่สูงกว่าเลเวลของข้อ, และ **ข้อความไม่ซ้ำกับข้ออื่นในไฟล์เดียวกัน**

## ชั้น 4 — AI ตรวจทานรอบสอง แล้วปิ๊กอนุมัติ

ให้ AI ตรวจซ้ำด้วย checklist นี้ทุกครั้ง (ระบุให้ครบ ไม่ใช่แค่ "ช่วยเช็กให้หน่อย"):

1. คำตอบถูกข้อเดียวจริงไหม มีตัวเลือกอื่นที่ก็ถูกด้วยหรือเปล่า
2. โจทย์กำกวมไหม ตีความได้หลายทางหรือเปล่า
3. ยากง่ายตรงเลเวล CEFR ที่ระบุไหม
4. ภาษาเป็นธรรมชาติแบบเจ้าของภาษาไหม
5. บริบท/วัฒนธรรมเหมาะกับผู้เรียนไทยไหม

บันทึกผลตรวจไว้ในฟิลด์ `reviewNotes` แล้วเปลี่ยน `reviewStatus` เป็น `reviewed`

จากนั้น:
1. เข้า `admin/import.html` → วางไฟล์ → กด "ตรวจไฟล์" (รอบนี้จะเช็คซ้ำกับของที่มีอยู่แล้วในคลังด้วย) → กด "นำเข้าเฉพาะข้อที่ผ่าน"
2. เข้า `admin/content.html` → กรองสถานะ `draft` → อ่านทีละข้อ แก้ได้ในหน้าเลย → กด **อนุมัติ** ทีละข้อหรือทั้งชุด

**นักเรียนเห็นเฉพาะข้อที่ `reviewStatus: published` เท่านั้น** และกฎนี้บังคับที่ Firestore security rules ไม่ใช่แค่ที่หน้าเว็บ — ข้อที่ยังไม่อนุมัติจึงอ่านไม่ได้แม้จะ query ตรงจาก devtools
