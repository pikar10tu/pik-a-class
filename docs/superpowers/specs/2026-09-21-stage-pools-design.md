# ด่านสุ่มข้อจากเงื่อนไข (Stage pools) — Design

**วันที่:** 2026-09-21
**สถานะ:** ตกลงกับปิ๊กครบแล้ว รอเขียนแผน
**ขอบเขต:** ก้อน A เท่านั้น — ก้อน B (ข้อชนิดเรียงประโยค `word_order`) แยกเป็น spec ของตัวเองหลังจากนี้

## 1. ปัญหา

ปิ๊กทดสอบเว็บจริงแล้วรายงานสองเรื่อง:

1. **"เล่นแต่ละรอบข้อมันเหมือนเดิม เรามีคลังใหญ่ก็อยากให้ใช้ประโยชน์"** — ด่านเก็บ `itemIds` เป็นรายชื่อข้อตายตัว เล่นกี่รอบก็ได้ข้อเดิมเรียงเดิม และโจทย์ที่เขียนเพิ่มทีหลังไม่เข้าด่านไหนเลยจนกว่าจะมีคนไปติ๊กเพิ่มด้วยมือ
2. ยังไม่มีข้อชนิดเรียงประโยคแบบ Duolingo — **แยกไปก้อน B**

เอกสารนี้แก้ข้อ 1

## 2. การตัดสินใจ และทางที่ไม่เลือก

### 2.1 ด่านมีคลังของตัวเอง สุ่มมาเล่นบางส่วน

พิจารณาสามทาง:

- **ให้ด่านสุ่มจากคลังรวมทั้งหมด** — ไม่เลือก เพราะ**เพดานดาวหายไป** เด็กเล่นด่านเดิมซ้ำเรื่อยๆ ก็เก็บดาวได้เรื่อยๆ ซึ่งย้อนกับเหตุผลที่ปิ๊กเลือกทำด่านก่อนแบบฝึกหัดอิสระตั้งแต่แรก (ดาวต้องมีเพดาน 3 ดาวต่อด่านถึงจะกลายเป็นวงจรไล่เก็บ)
- **ด่านคงที่ แล้วเพิ่มโซนฝึกอิสระแยก** — ตรงกับ `PLAN.md` §8 ที่ยืนยันว่า "ด่าน / แบบฝึกหัดอิสระ / การบ้าน — สามระบบแยกกันอยู่คู่กัน" แต่เป็นงานก้อนใหม่ทั้งก้อน และไม่ได้แก้ปัญหาที่ปิ๊กเจอตรงหน้า
- **เลือก: ด่านมีคลังของตัวเอง สุ่มมาเล่นรอบละ N ข้อ** — ข้อไม่ซ้ำทุกรอบ และ**ยังมีเพดานดาวต่อด่าน** เพราะ 3 ดาวหมายถึงทำถูกหมดในชุดที่สุ่มได้รอบนั้น

โซนฝึกอิสระยังคงเป็นงานแยกในอนาคต ไม่ถูกยกเลิกโดย spec นี้

### 2.2 คลังของด่านมาจากเงื่อนไข ไม่ใช่รายชื่อข้อ

- **เลือกข้อเข้าด่านด้วยมือ (มีเยอะขึ้นแล้วสุ่ม)** — ไม่เลือก เพราะไม่ได้แก้ปัญหาเลย คลังจะใหญ่ขึ้นแต่ด่านนิ่งอยู่จนกว่าจะมีคนไปเติม และงานเลือกข้อหนักขึ้นสามเท่า
- **เลือก: ด่านเก็บเงื่อนไข (สกิล + ระดับ + แท็ก)** — เขียนโจทย์ใหม่ติดแท็กถูกแล้ว**เข้าด่านเองอัตโนมัติ** ไม่ต้องกลับมาแก้ด่าน
- **ผสม (เงื่อนไข + ปักหมุด/กันออกรายข้อ)** — ไม่เลือกตอนนี้ตามหลัก YAGNI เพิ่มทีหลังได้โดยไม่ต้องรื้อ

**บริบทที่ทำให้ข้อนี้สำคัญกว่าที่คิด:** ปิ๊กไม่ได้เพิ่มเนื้อหาด้วยมือ แต่สั่ง AI เขียนเป็นชุด ดังนั้น **แท็กคือจุดเชื่อมเดียวระหว่างเนื้อหากับด่าน** ติดแท็กผิดนิดเดียว = ข้อนั้นไม่โผล่ในด่านไหนเลยและไม่มีใครรู้ เพราะไม่มีการติ๊กเลือกด้วยมืออีกแล้ว → จึงต้องมี**ตัวจับข้อกำพร้า** (§6)

### 2.3 จำนวนข้อต่อรอบ

**เลือก: ค่าเริ่มต้นทั้งระบบ แก้รายด่านได้** (`DEFAULT_DRAW_COUNT = 7`) — ปิ๊กสร้างด่านได้โดยไม่ต้องตั้งอะไร แต่ด่านทบทวนรวมตั้งให้ยาวกว่าได้

**คลังไม่พอ → เล่นเท่าที่มี** ไม่ซ่อนด่าน เพราะเด็กไม่ควรเจอด่านหายไปเฉยๆ โดยไม่มีคำอธิบาย ฝั่งแอดมินขึ้นเตือนแทน

## 3. Data model

### 3.1 `stages` — ฟิลด์ที่เปลี่ยน

| ฟิลด์ | เดิม | ใหม่ |
|---|---|---|
| `itemIds` | `string[]` 1–20 รายชื่อข้อ | **ลบออก** |
| `tags` | — | **เพิ่ม** `string[]` 1–30 แท็กที่ด่านนี้ดึง |
| `drawCount` | — | **เพิ่ม** `int` 1–30 จำนวนข้อต่อรอบ |

ฟิลด์อื่นคงเดิมทั้งหมด (`skill`, `level`, `order`, `title`, `passThreshold`, `isPreview`, `reviewStatus`, `createdAt`, `updatedAt`, `createdBy`)

`tags` มีได้หลายอันเพื่อรองรับด่านทบทวนรวม เช่น
`["grammar:past-simple", "grammar:past-continuous", "grammar:present-perfect"]`

เพดาน 30 มาจากข้อจำกัดของ Firestore `array-contains-any`

### 3.2 การดึงคลังของด่าน

เพิ่ม `stagePoolConstraints({ skill, level, tags, tier })` ใน `queries.js` คืน:

```
reviewStatus == 'published'
visibility   == 'bank'
skill        == <skill>
level        == <level>
tags         array-contains-any <tags>
isPreview    == true            // เฉพาะเมื่อ tier !== 'full'
```

เกณฑ์เดียวกับ `bankExerciseConstraints` ที่มีอยู่แล้ว บวกเงื่อนไขแท็ก — ตั้งใจให้สองที่ไม่เพี้ยนจากกัน

**ผลพลอยได้ที่สำคัญ:** ปัจจุบัน `fetchStageExercises` ดึงด้วย `documentId() in [...]` ซึ่ง (ก) มีเพดาน 30 ข้อ และ (ข) **ถ้ามีข้อใดข้อหนึ่งที่ผู้เล่นไม่มีสิทธิ์อ่าน Firestore ปฏิเสธทั้ง query** ด่านพังทั้งด่านโดยไม่มีทางรู้ว่าข้อไหน การเปลี่ยนมาใช้เงื่อนไขทำให้เงื่อนไขสิทธิ์อยู่ใน query เอง ผู้เล่นได้เฉพาะข้อที่ตัวเองอ่านได้ ไม่มีทางพังทั้งด่านอีก และเพดาน 30 หายไป

### 3.3 ขนาดคลัง

ไม่ใส่ `limit()` ในรอบนี้ เพราะ `limit` ที่ไม่มี `orderBy` จะได้ "ข้อแรกๆ ตามลำดับ document id" ซึ่งเป็น**ชุดเดิมทุกครั้ง** — กลายเป็นอคติถาวรที่มองไม่เห็น แทนที่จะสุ่มจริง

สมมติฐาน: คลังต่อด่านอยู่ในหลักสิบถึงต้นๆ ร้อย ถ้าโตเกิน **200 ข้อ** หน้าแอดมินจะเตือนให้ซอยแท็กให้ละเอียดขึ้น และค่อยกลับมาทบทวนเรื่อง paging

## 4. หนึ่งรอบเล่น

1. เข้าด่าน → ดึงคลังตามเงื่อนไข (§3.2)
2. **สุ่มเลือก `drawCount` ข้อ แล้วสลับลำดับ** — ตรรกะบริสุทธิ์ รับ `random` แบบฉีดเข้าได้ เพื่อให้เทสตรึงผลได้
3. เล่นตามปกติ ตรวจคำตอบด้วย `grading.js` เดิม
4. ดาวคิดจาก**สัดส่วนที่ถูกในรอบนั้น** — 3 ดาว = ถูกหมดในรอบนั้น เพดานยังอยู่
5. บันทึกผลผ่าน `saveStageResult` เดิม ไม่เปลี่ยน

**สุ่มใหม่ทุกครั้ง ไม่จำรอบก่อน** — ตั้งใจให้เรียบง่าย ถ้าคลังใหญ่กว่าจำนวนที่สุ่มพอสมควร โอกาสได้ชุดเดิมเป๊ะต่ำมาก

**ผลข้างเคียงที่ดี:** `buildWordBank` สร้างตัวเลือกของข้อเติมคำจากข้ออื่น**ในรอบนั้น** พอชุดข้อเปลี่ยนทุกรอบ ตัวเลือกลวงก็เปลี่ยนตาม ข้อเดิมจึงไม่ได้ง่ายขึ้นจากการจำตัวเลือก

## 5. หน้าสร้างด่าน (แอดมิน)

เปลี่ยนจาก "ติ๊กเลือกข้อทีละข้อ" เป็น:

- เลือก **แท็ก** (checkbox จาก taxonomy ของระดับนั้น — รูปแบบเดียวกับที่หน้าออกข้อใช้อยู่แล้ว)
- ตั้ง **จำนวนข้อต่อรอบ** (ค่าเริ่มต้น 7)
- **แสดงผลทันทีว่าเงื่อนไขนี้ตอนนี้มีกี่ข้อ** พร้อมตัวอย่างข้อที่เข้าเงื่อนไข — เพื่อให้รู้ว่าตั้งถูกไหมโดยไม่ต้องเดา
- **เตือนเมื่อคลังน้อยกว่าจำนวนที่ตั้งไว้** บอกตรงๆ ว่ารอบหนึ่งจะได้กี่ข้อจริง

`validateStage` เปลี่ยนตาม: ข้อผิดพลาดชุด `itemIds` เดิม (ไม่มีข้อ / เกิน / ข้อถูกลบ / ชนิดไม่รองรับ) ถูกแทนด้วย
- `tags` — ต้องเลือกอย่างน้อยหนึ่งแท็ก
- `drawCount` — ต้องอยู่ในช่วง 1–30

ข้อสังเกตจากรีวิว Task 10 ยังใช้ได้: `validateStage` ไม่ตรวจ `level`/`skill` กับ taxonomy ฟอร์มจึงต้องบังคับด้วย dropdown ต่อไป

## 6. ตัวจับข้อกำพร้า

ฟังก์ชันบริสุทธิ์: รับรายการด่านกับรายการข้อ คืนข้อที่ `reviewStatus === 'published'` และ `visibility === 'bank'` แต่**ไม่เข้าเงื่อนไขของด่านใดเลย**

แสดงในหน้าคลังเนื้อหาเป็นป้ายเตือนพร้อมจำนวนและรายการ — กันเคสที่ AI เขียนโจทย์แล้วติดแท็กผิด ข้อนั้นจะหายเงียบไปจากระบบ

## 7. ย้ายของเดิม

มีด่านอยู่ 4 ด่าน ทั้งหมดเป็นฉบับร่างและผมเป็นคนสร้างเอง ไม่มีนักเรียนเล่นแล้ว → **ไม่ต้องทำ migration แบบค่อยเป็นค่อยไป ลบแล้วสร้างใหม่ตามโครงใหม่ได้เลย**

| ด่าน | แท็ก | `drawCount` |
|---|---|---|
| 1 Past Simple | `grammar:past-simple` | 7 |
| 2 Past Continuous | `grammar:past-continuous` | 7 |
| 3 Present Perfect | `grammar:present-perfect` | 6 |
| 4 ทบทวนรวม | ทั้งสามแท็ก | 10 |

`stageClears` / `submissions` ที่มีอยู่ไม่ต้องแตะ — ผูกกับ `stageId` และ `exerciseId` ซึ่งไม่เปลี่ยนความหมาย

### 7.1 ⚠️ ทันทีหลังย้าย ด่าน 1–3 จะยังไม่สุ่มอะไรเลย

ตรวจกับเนื้อหาจริงแล้ว คลังปัจจุบันคือ `past-simple` 7 ข้อ · `past-continuous` 7 ข้อ · `present-perfect` 6 ข้อ

เทียบกับ `drawCount` ใน §7 จะเห็นว่า **ด่าน 1–3 มีข้อในคลังเท่ากับจำนวนที่สุ่มพอดี** → สุ่มแล้วก็ได้ทุกข้ออยู่ดี เปลี่ยนแค่**ลำดับ** ส่วนด่าน 4 มีคลัง 20 ข้อ สุ่ม 10 จึงจะต่างจริงทุกรอบ

**แปลว่าโค้ดที่ถูกต้องสมบูรณ์จะยังให้ความรู้สึกว่า "ไม่มีอะไรเปลี่ยน" ในด่าน 1–3** — ฟีเจอร์นี้จะออกดอกผลก็ต่อเมื่อคลังต่อแท็กโตกว่าจำนวนที่สุ่ม

ผลที่ตามมาต่อการวางแผน:
- **อย่าใช้ "เล่นสองรอบแล้วข้อต่างกัน" เป็นเกณฑ์ตรวจรับของด่าน 1–3** จะสรุปผิดว่าโค้ดพัง ให้ตรวจที่ด่าน 4 หรือเติมเนื้อหาก่อน
- งานเขียนเนื้อหาเพิ่มต่อแท็ก (ซึ่งตกที่ผม) คือสิ่งที่ทำให้ฟีเจอร์นี้มีความหมายจริง ควรตามมาติดๆ — เป้าหมายคร่าวๆ ที่ทำให้รู้สึกได้คือคลังราวสองเท่าของ `drawCount` ขึ้นไป

## 8. Firestore rules และ index

**Rules:** ไม่ต้องแก้ กฎของ `exercises` กันเรื่อง tier/preview อยู่แล้ว และ query ใหม่ใส่เงื่อนไขให้ตรงกับกฎ

**Index:** ต้องเพิ่ม composite index ของ `exercises` สำหรับชุดเงื่อนไขใหม่ (equality หลายตัว + `array-contains-any`) ทั้งแบบมีและไม่มี `isPreview`

> **บทเรียนจากรอบที่แล้ว:** emulator สร้าง index ให้อัตโนมัติ ทำให้เทสเขียวทั้งที่ production จะตอบ `failed-precondition` — **index ต้องถูกเพิ่มลง `firestore.indexes.json` และตรวจบน production จริง ไม่ใช่เชื่อเทสในเครื่อง**

## 9. เคสขอบ

| เคส | พฤติกรรม |
|---|---|
| คลังน้อยกว่า `drawCount` | เล่นเท่าที่มี ดาวคิดจากที่เล่นจริง แอดมินเห็นคำเตือน |
| คลังว่าง (ไม่มีข้อเข้าเงื่อนไขเลย) | ใช้ข้อความ "ด่านนี้ยังไม่มีข้อเลย" ที่มีอยู่แล้ว แอดมินเห็นคำเตือน |
| ปิ๊กถอนอนุมัติข้อระหว่างที่เด็กกำลังเล่น | รอบที่กำลังเล่นสุ่มไปแล้วฝั่งไคลเอนต์ ไม่กระทบ รอบถัดไปจึงเปลี่ยน |
| เด็ก tier free | เงื่อนไข `isPreview` อยู่ใน query ได้เฉพาะข้อที่อ่านได้ ไม่พังทั้งด่าน |
| แท็กในด่านไม่มีข้อเลยสักข้อ | เท่ากับคลังว่าง |

## 10. การทดสอบ

**ตรรกะบริสุทธิ์ (unit):** การสร้างเงื่อนไข, การสุ่มเลือกด้วย `random` ที่ฉีดเข้าได้ (ตรึงผลได้ / ไม่เกิน `drawCount` / ไม่ซ้ำข้อในรอบเดียว / คลังน้อยกว่าที่ตั้งได้เท่าที่มี), `validateStage` ชุดใหม่, ตัวจับข้อกำพร้า

**Rules test (emulator):** นักเรียน tier free ยิง query ชุดใหม่ต้องผ่านและได้เฉพาะข้อ preview · tier full ได้ครบ · **ทดสอบด้วยบัญชีที่ไม่ใช่ admin เสมอ** เพราะ `isAdmin()` ลัดผ่านทุกเงื่อนไขและนั่นคือสาเหตุที่บั๊กใหญ่รอดมาถึงรีวิวรอบสุดท้ายในรอบก่อน

**บน production:** ต้องยืนยันว่า index ทำงานจริง และเดินโฟลว์ด้วยบัญชีนักเรียนจริง

## 11. นอกขอบเขต

- ก้อน B: ข้อชนิด `word_order` (เรียงประโยคจากภาษาไทยด้วยชิปคำ + คำลวงที่เขียนเอง รับหลายลำดับผ่าน `answerKey`) — spec แยก
- โซนแบบฝึกหัดอิสระที่สุ่มจากคลังรวมไม่จำกัด — ยังอยู่ในแผนระยะยาว
- การปักหมุด/กันออกรายข้อในด่าน
